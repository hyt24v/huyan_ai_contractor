# ColaMD 设计审计报告 —— 供「AI 包工头」借鉴

> 调研对象:[marswaveai/ColaMD](https://github.com/marswaveai/ColaMD)(★~1.3K,MIT,macOS/Windows/Linux)
> 调研日期:2026-10-25。调研方式:官网(colamd.com)、README/README_CN、CLAUDE.md、Releases 更新日志、PR/Issue(因网络限制未能浅克隆源码,源码级结论均标注了出处与置信度)。

## 0. 一句话结论

ColaMD 的本质是「**文件即真相 + 渲染只是投影**」:技术栈 Electron + Milkdown(ProseMirror),用 `fs.watch` 做磁盘热更新作为第一卖点("Agent Native"),用「如非必要勿增实体」做减法哲学。对 AI 包工头最有价值的不是它的编辑器内核(我们是 Monaco,抄不动也不必抄),而是它围绕"磁盘文件会被 Agent 改"这一前提做的**一整套同步 UX 与防数据损坏设计**。

## 2. 编辑器 UX 核心设计

### 2.1 True WYSIWYG(无分屏)
- 单视图:渲染结果直接"覆盖"在文本上,眼睛不用在两个 pane 之间来回跳(官网/教程文)。
- **演进细节值得注意**:v2.7.2 之前是 Typora 式混合——光标停在哪行,哪行就露出 `**`、`#`、`[]()` 源码标记;v2.7.5 把这个模式**删掉了**,渲染模式下每行都是干净排版,要改标记去源码模式(`⌘/`)。作者理由:光标移动导致屏幕排版一直变,是干扰。(Releases v2.7.5)
- **文件即真相的硬核兑现**:v2.7.2 换了编辑器内核。旧内核把文件解析成内部副本、保存时重新序列化,导致"你没碰过的字符也被改写"(表格分隔行被压缩、`* $ _` 被加反斜杠);新内核"编辑器里存的就是文件的字节,渲染只是叠在上面的一层装饰,打开什么样,保存就还是什么样"。v2.7.5 顺带修掉"复制到别处多一个空行";v2.4.4 修了保存时破坏 YAML frontmatter、CRLF 变 LF 的问题。(Releases v2.7.2 / v2.7.5 / v2.4.4)
- 对配置文件编辑器而言,这条「无损 round-trip」是**信任地基**:用户敢拿它指着自己已有的文件。

### 2.2 Always in Sync(磁盘热更新)——重点分析

这是 ColaMD 的第一优先级功能(CLAUDE.md「核心功能优先级」第 1 条),实现链路(README_CN「工作原理」+ CLAUDE.md 项目结构 + PR #8 + Releases v1.6):

```
AI Agent/脚本/其他编辑器 → 写入 .md 文件 → fs.watch 检测变化 → ColaMD 自动刷新
```

- **监听在主进程**:`src/main/index.ts` 负责窗口管理、文件 I/O、菜单、**文件监听**(CLAUDE.md),渲染进程通过 preload 的安全 IPC 桥接收通知。
- **用 `fs.watch` + debounce**:PR #8 提到 "clear pending debounce and rewatch timers",说明有防抖与 watcher 轮换计时器。
- **踩过的坑(对 AI 包工头直接有用)**:
  1. **原子写入(atomic save)陷阱**:很多编辑器和 AI 工具保存时写临时文件再 rename 覆盖,`fs.watch` 发出的是 `rename` 而非 `change`,旧 watcher 还挂在被替换掉的 inode 上,之后的更新全部丢失。v1.6 修复:"atomic-save (rename) detection, watcher self-recovery"——检测 rename、**重新建立 watcher**、watcher 出错后自愈。(PR #8 / Releases v1.6)
  2. **自己保存触发的回声**:README 版本史与更新日志未见明确描述,但从"点击放映前先把当前内容写盘"(v1.5.0 commit)可推断它需要区分"自己写入"和"外部写入"(研究推断,见「缺失证据」)。
- **未保存修改时的冲突处理**:**未找到官方文档明确说明**。已知事实是脏状态存在(v2.7.2:"有未保存内容的窗口照旧先问你怎么存"——仅指关窗时)。磁盘变化 + 本地脏 的具体策略(直接覆盖?提示?)README/官网/Releases 均未写明(见「缺失证据」)。
- **UX 反馈闭环**:不只是默默刷新——标题栏的 Agent 活动指示器(橙色呼吸=写入中,绿色闪现=完成)让用户**知道**此刻是 Agent 在干活,这是"结对编程"体感的关键(v1.3,README_CN)。

### 2.3 文件浏览与大纲切换
- 同一个**浮动面板**承载两种内容:当前目录的 Markdown 文件列表 ↔ 当前文档大纲(标题跳转+当前节高亮)。
- 面板可拖拽调宽,可放左或右;v2.7.6 修了一个回归:面板浮在窗口上,正文要**给面板让位并在剩余可见区域里居中**(而不是被压住);且切到源码模式时文字不横向跳——两种模式落在**同一个阅读位置**上。(官网/Releases v2.7.6)
- 没有常驻侧栏、没有文件树/工作区——面板是"按需唤出的浮层",不是布局的一部分。

### 2.4 任务列表 checkbox
v1.6.1:"Editable task lists (click / ⌘+Enter)"——渲染态下复选框直接可点,点击即改源文件,也有快捷键。

### 2.5 Mermaid / 高亮 / LaTeX / 图片导出
- Mermaid:早期用隐藏 iframe 渲染避免卡打字;v2.7.7 换 Pele 引擎,按图种懒加载(无图的文件零开销),颜色**从当前主题计算**,换主题不用重画。
- 代码高亮、KaTeX 公式(就地编辑)、脚注悬停均在 v2.7 内核补齐。
- 图片导出:连续长 PNG,可选桌面/移动两种阅读宽度,超长文档自动切成编号页序列(明显面向社交媒体分享场景)。

## 3. "Minimal by Design" 哲学:减法怎么做才不损失功能

CLAUDE.md 第一原则「如非必要,勿增实体」:每加一个 UI 元素/功能/一行代码,先问是否绝对必要,默认答案是否。具体取舍:

| 砍掉的 | 功能入口藏到哪 |
|---|---|
| 工具栏 | Markdown 语法本身 + 快捷键 + 原生应用菜单(File/Edit/View/Theme/Help) |
| 常驻侧边栏 | 文件/大纲做成**可拖宽的浮动面板**,按需唤出;正文居中让位 |
| 状态栏 | Agent 状态压缩成**标题栏一个小圆点**(橙呼吸/绿闪) |
| 设置页 | "nothing to configure"(官网):主题走 Theme 菜单,自定义主题靠导入 CSS 文件到 `~/.colamd/`,语言跟随/切换在菜单层 |
| 标签条 | 只在打开第二个文档时才出现(README) |
| 源码标记常驻显示 | v2.7.5 删除光标行露源码的混合模式,收进独立的 Source Mode(`⌘/`) |

配套纪律(CLAUDE.md「不做的事情」):不做文件管理/工作区、不做知识库、不做云同步协作、不做笔记组织与标签、不加不必要 UI。——**用"不做清单"保护"做少"**。

## 4. 设置项(可配置项清单)

ColaMD 自称"nothing to configure",实际存在的用户可配置面(依据 README/README_CN/官网/Releases):

1. **主题**:12 套内置 + 导入自定义 CSS(Theme > Import Theme,存 `~/.colamd/themes/`),选择持久化
2. **界面语言**:中文 / English
3. **文件/大纲面板**:显隐、宽度(拖拽)、停靠左右侧(v2.7.6 暗示两侧皆可)
4. **Source Mode 开关**(`⌘/`)
5. **图片导出宽度模式**:桌面 / 移动阅读宽度(README)
6. 拼写检查:固定关闭(非用户项,v1.6)
7. 标签页行为:无配置,自动出现/消失

**没有**字号/字体/行宽/缩进等编辑器细调项——排版全部封装在主题 CSS 里。这是刻意的:把"配置"转化为"换主题/写 CSS"。

## 5. 视觉语言

- **阅读宽度居中**:正文按固定阅读宽度在窗口中居中;面板打开时正文在**剩余可见区域**内居中,且渲染/源码两模式共享同一阅读位置(v2.7.6)。具体 px 值官方未公开(fork 版 HTML 导出用 780px 居中、行高 1.75,仅作参考,非上游事实)。
- **字体随主题**:12 套主题对应 12 种完整排版性格(衬线/无衬线、暖纸/冷底),字体栈封装在各主题 CSS 内;自定义主题=覆盖 CSS 变量与选择器,官方提供带注释模板。
- **间距与空行语义**:空行=段落分隔,不再翻成空段落(v2.7.5)——排版上的"呼吸感"同时是数据正确性问题。
- **主题保真贯穿导出**:PDF/Word/HTML/图片导出都带当前主题配色;Mermaid 颜色从主题计算(v2.7.7)。
- **极简窗口**:macOS 全屏不为不存在的红绿灯按钮留位、Windows 从三条堆叠栏收成一条 shell 行(v2.4.x);焦点环颜色跟随主题而非系统强调色(README 版本史)。

## 6. 对「AI 包工头」的可借鉴点

背景对齐:AI 包工头是 Tauri(React+Monaco)的 VS Code 风格**配置工具**,用户编辑 agent 配置/prompt 文件,这些文件同时会被 agent 自己或脚本修改——这正是 ColaMD 的核心场景,但我们的产品形态不同(有侧栏、有 Monaco、是管理台不是写作工具),所以**借鉴 UX 决策,不抄形态**。

### 6.1 重点:磁盘变更自动同步(对 AI 包工头价值极大,建议 P0)

ColaMD 证明了这条链路的关键决策点,逐条对应:

| ColaMD 的做法(出处) | AI 包工头落点 | 优先级 |
|---|---|---|
| 监听放在主进程/后端,前端只收事件(CLAUDE.md: main/index.ts 文件监听) | Rust 后端用 `notify` crate 监听已打开的配置文件,经 Tauri event 推给前端;前端不直接 watch(符合 FsPort 架构:fs 访问统一走后端) | **P0** |
| 原子写入 rename 检测 + watcher 自愈重建(v1.6 / PR #8) | Rust `notify` 同样会踩 rename 坑:收到 `Rename`/`Remove` 事件后必须**重新注册 watcher**,并对事件做去抖合并 | **P0** |
| 区分"自己保存"与"外部写入"(推断,见缺失证据) | 前端保存成功后记录最近一次写入的内容哈希/时间戳,watch 事件回来先比对,是自己写的就忽略,避免 Monaco 被回声刷新打断光标 | **P0** |
| Agent 活动指示器:标题栏圆点,橙呼吸=写入中,绿闪=完成(v1.3) | Markdown/JSON 编辑器页头部(或 tab 上)加一个「外部变更」指示:文件刚被 agent 改过 → 短暂高亮/toast,并标注来源时间;比静默刷新更建立信任 | **P0** |
| 干净状态直接刷新;脏状态策略未公开(缺失证据) | 我们的编辑器有编辑历史+快照,可做得比 ColaMD 更好:**无本地未保存修改→静默重载;有未保存修改→不覆盖,弹"文件已被外部修改:加载磁盘版本 / 保留我的编辑 / 对比"三选**,加载前先 `snapshotNow()` 兜底 | **P0** |
| 文件即真相、无损 round-trip(v2.7.2 内核更换的全部动机) | JSON 编辑器尤其要守住:保存只改用户改过的部分,不重排整个文件(键序、注释、尾逗号尽量保留);YAML/JSONC 配置文件被编辑器"顺手改写"是最伤信任的 | **P0** |
| 同目录文件列表自动发现 agent 新建的文件(v1.7) | 配置套餐/agent 目录下的文件列表(Skills、MCP、prompt 管理页)监听目录变化自动刷新,agent 新装的 skill 不用手动刷新就可见 | **P1** |

### 6.2 编辑器 UX 借鉴(按页面映射)

**Markdown 编辑器页**
- **P1** 大纲(heading 跳转+当前节高亮):Monaco 有现成的 document symbol,做一个可唤出的浮层大纲,长 prompt 文件导航收益大。
- **P1** 查找/替换的"下一个真的跳过去"细节(ColaMD 曾踩坑:计数在走界面不动):检查我们 Monaco 集成的 find 是否正确定位滚动。
- **P1** ⌘/ 式"阅读模式":预览渲染态与源码态切换时保持**同一滚动位置/阅读位置**(v2.7.6 的教训:别让文字横跳)。
- **P2** 智能换行(单换行即换行):如果未来加 Markdown 预览,agent 写的 md 多为单换行风格,预览渲染应匹配。
- **P2** 富文本复制(带格式粘贴到微信/飞书/邮件):用户常要把 prompt/配置说明贴给同事,Monaco 复制纯文本,可加"复制为富文本/HTML"。
- **P2** 任务列表 checkbox 在预览态可点击(如果我们加渲染预览)。
- **P2** 导出:Markdown 页导出自包含 HTML/图片(带主题色),用于分享配置文档。优先级低,我们有更核心的管理功能。

**JSON 编辑器页**
- **P0** 磁盘热同步(见 6.1,JSON 配置文件被 agent 改的频率最高)。
- **P1** "保存不顺手改写":JSON 保存保持键序与格式;已有防抖快照机制可继续作为冲突时的后悔药。
- **P2** 错误定位体验:ColaMD 初始化失败写 `userData/renderer-errors.log` 而非白屏(v2.7.2)——我们 JSON 解析失败时的错误展示可对照检查。

**全局/其他**
- **P1** 更新后首次启动展示更新日志(README "Version Changelog"):我们的 beta 线迭代快,用户感知"这次更新了什么"的成本很低。
- **P2** "标签条只在需要时出现"的渐进式 UI 思路:编辑器区默认纯净,辅助 UI(历史下拉、大纲、同步指示)按需浮现,契合 VS Code 风格但不堆栏。
- **P2** 主题即 CSS 文件+可导入:我们的主题系统已是 token 化(themes.ts),可考虑导出/导入主题文件,让社区主题成为可能。

### 6.3 哲学层借鉴
- 「如非必要勿增实体」+ **明确的"不做清单"**:ColaMD 把不做的事写进 CLAUDE.md 保护产品边界。AI 包工头也可在 AGENTS.md 里固化"不做"清单(如:不做笔记库、不做云同步),防止功能膨胀。
- **状态压缩成环境信号而非面板**:Agent 活动用一个呼吸圆点表达,不打断、不占位。我们有多 agent 运行状态,同样适合"环境化"呈现(活动栏徽标/呼吸点)而非弹窗。

## 7. 矛盾点记录

1. **幻灯片形态**:README_CN 说 `File → Open as Slides(⌘⇧P)` 起本地服务在**浏览器**放映;而 Releases(v2.x)描述的是**应用内全屏**放映(`---` 分页、光标页起播、Esc 落回原页)。判断为功能演进(浏览器放映 → 应用内放映),两版描述对应不同版本,非真正冲突。
2. **任务列表/高亮/大纲归属**:PR #14(search+LaTeX)来自社区贡献者;fork 版(ColaMD-extend)也有插件化 math/mermaid。本报告只把上游 README/官网/Releases 明确列出的算作 ColaMD 本体功能。
3. **v2.7.2 提到"光标裸露的那一行露源码",v2.7.5 又把该模式删除**——是快速自我修正,说明"混合模式"在实践中被作者判定为干扰,对我们做"预览/源码"切换是重要参考:**不要试图两者叠加**。

## 8. 缺失证据(未能验证)

1. **脏缓冲区 + 磁盘变更的冲突策略**:ColaMD 官方文档未说明"本地有未保存修改时磁盘被改"的处理(直接覆盖/提示/合并)。这是 AI 包工头借鉴时必须自行设计的部分(6.1 已给方案)。建议后续浅克隆 `src/main/index.ts` 与 renderer 同步逻辑源码确认。
2. **是否输入即自动保存/保存时机**:仅有间接证据(v1.5.0 "放映前自动写盘"、v2.7.2 关窗询问未保存),说明**不是**每次击键落盘;防抖/失焦保存的具体策略未见文档。
3. **上游阅读宽度的具体数值(px/ch)、字体栈细节**:官方未公开数字;fork 版 780px/行高 1.75 仅供参考。
4. **"Pele" 图表引擎**:release notes 称其为 Obsidian 团队所做、兼容 Mermaid 语法;未独立核实该项目身份(疑为笔误或新项目),引用时注意。
5. 源码级实现细节(未克隆仓库):watcher 的去抖毫秒数、重读前的 mtime/size 比对、大纲数据流等。

## 9. 最值得抄的 Top 5

1. **磁盘热更新全链路(P0)**:后端(Rust/notify)监听已打开文件 → 事件去抖 → 区分自写回声 → 干净静默刷新 / 脏三选提示(加载/保留/对比,先 snapshot 兜底)。这是 ColaMD 的第一卖点,也是 AI 包工头"配置文件被 agent 改"场景的直接答案。
2. **rename 原子写入的 watcher 重建与自愈(P0)**:不处理这个,监听功能上线即半残(ColaMD 用 v1.6 整个版本修的坑)。
3. **外部变更的环境化指示(P0/P1)**:标题栏/tab 上的呼吸圆点(写入中→完成闪现),让用户对"agent 正在动我的文件"有体感,而不是面对静默变化的屏幕。
4. **文件即真相、保存零改写(P0)**:打开什么样保存就什么样,键序/frontmatter/CRLF 不动——配置编辑器的信任地基,JSON 页尤其要守住。
5. **"如非必要勿增实体"+ 不做清单(P1)**:辅助 UI(大纲/历史/指示)按需浮现、状态压缩为环境信号,以及把"不做的事"写进项目规则防膨胀。
